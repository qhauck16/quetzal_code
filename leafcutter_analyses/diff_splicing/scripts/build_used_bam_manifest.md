# build_used_bam_manifest.R

**Purpose & context** — Written 2026-09-25 before the local TCGA RNA-seq BAMs
were deleted. Records exactly which GDC files the leafcutter runs used, so any
result can be regenerated by re-downloading them (`gdc-client download -m
download/used_bams.gdc_manifest.txt`). "Used" = every rail_id in
`results/*/bams_used.tsv` + `control_results/*/bams_used.tsv` (573 samples,
571 unique files).

**Decision rationale**
- The samples came from several download rounds, including older per-gene ones
  (`deprecated/`, `spop/`, `idh1/`), so file_ids are looked up in *every* saved
  `metadata.cohort*.json`, not just the 2026-04-20 plan. `sample_plan.tsv` alone
  is not the record: 278 of the 573 used samples are not in it.
- Each record is verified against the BAM on disk by exact byte size (573/573
  at the time of deletion).
- 24 samples had no JSON record or a size mismatch; those were resolved with a
  GDC API query saved in `download/gdc_api_rnaseq_bams_2026-09-25.tsv`.

**Gotchas & warnings**
- **Aliquot mix-up.** For 13 used rail_ids, the BAM on disk was a *different
  aliquot of the same patient* from the barcode recount3 lists for that
  rail_id. For example, the metadata says `-11A` (solid-tissue normal), `-06A`
  (metastatic) or `-02A` (recurrent), but the BAM's `@RG SM` is the `-01A`
  primary tumour. The download sorter apparently matched on the patient rather
  than the aliquot. The manifest records the file actually used
  (`aliquot_on_disk`), so re-downloading reproduces the published results,
  including this error. See `download/bam_sm_check_unresolved.tsv`.
- Because of that, two GDC files each back two rail_ids: 472119 and 870753
  both got DV-A4W0 `-01A`; 55126 and 438998 both got ER-A2NF `-01A`, which are
  both SF3B1 test samples. The manifest is de-duplicated.
- The API table is a snapshot. GDC can retire files; `state` is recorded.
- After deletion, the size check reports `disk_size` NA. Re-running this script
  then only confirms file_ids, not sizes.

**User preferences** — Quinn wants every result reproducible after the BAMs are
deleted; the manifest must record what was actually used, not what was
intended.

**Input/output**
- In: `results/*/bams_used.tsv`, `control_results/*/bams_used.tsv`,
  `download/bam_inventory.tsv`, `**/metadata.cohort*.json`,
  `../../../tcga_v2_samples.tsv`, `download/bam_sm_check_unresolved.tsv`,
  `download/gdc_api_rnaseq_bams_2026-09-25.tsv`.
- Out: `download/used_bams.gdc_manifest.txt` (gdc-client format: id, filename,
  md5, size, state) and `download/used_bams.rail_map.tsv` (rail_id → barcode,
  aliquot_on_disk, runs, file_id, sizes, source).
- The deletion itself is logged in `download/deleted_bams_2026-09-25.log`.

```
results/*/bams_used.tsv ─────┐
control_results/*/bams_used ─┤
bam_inventory.tsv ───────────┤
metadata.cohort*.json ───────┼──► build_used_bam_manifest.R ──► used_bams.gdc_manifest.txt ──► gdc-client
gdc_api_rnaseq_bams_*.tsv ───┤                               └─► used_bams.rail_map.tsv
bam_sm_check_unresolved.tsv ─┘
```

**2026-09-25, after deletion: FROZEN.** The script now refuses to run unless
every used BAM is on disk. Re-run without the BAMs, it picked a different
GDC file for 11 samples (an aliquot has genomic/transcriptome/chimeric BAMs;
only the size match chose correctly) and could pick a never-used file for
55126. `download/used_bams.*` and the other 2026-09-25 records are read-only
(`chmod a-w`). The relabel in `fix_sample_mislabels.R` does not touch them:
they describe the existing results, mislabels included.
